## 📋 Wireframe Artifacts Table Schema

### Table Name
```
wireframe_artifacts
```

### Complete Column Definitions

| Column | Type | Nullable | Default | Purpose |
|--------|------|----------|---------|---------|
| `id` | VARCHAR(36) | NO | PRIMARY KEY | Unique wireframe identifier (UUID) |
| `project_id` | VARCHAR(36) | YES | NULL | Link to parent project |
| `research_id` | VARCHAR(36) | YES | NULL | Link to source research result |
| `title` | VARCHAR(255) | NO | - | Wireframe title |
| `design_type` | VARCHAR(50) | YES | NULL | Design pattern (e.g., 'responsive') |
| `svg_content` | TEXT | YES | NULL | Generated SVG wireframe markup |
| `layout_json` | JSONB | YES | NULL | Wireframe layout structure (screens/blocks) |
| `screens` | JSONB | YES | NULL | Individual screen data objects |
| `suggested_components` | JSONB | YES | NULL | **NEW** - Component recommendations |
| `design_suggestions` | JSONB | YES | NULL | **NEW** - UX improvement suggestions |
| `status` | VARCHAR(50) | YES | 'draft' | Wireframe state (draft/generated/approved/rejected) |
| `created_at` | TIMESTAMP | YES | NOW() | Record creation timestamp |
| `updated_at` | TIMESTAMP | YES | NOW() | Last modification timestamp |
| `version` | INTEGER | YES | 1 | Version number for tracking changes |

### SQL Create Statement

```sql
CREATE TABLE IF NOT EXISTS wireframe_artifacts (
  id VARCHAR(36) PRIMARY KEY,
  project_id VARCHAR(36),
  research_id VARCHAR(36),
  title VARCHAR(255) NOT NULL,
  design_type VARCHAR(50),
  svg_content TEXT,
  layout_json JSONB,
  screens JSONB,
  suggested_components JSONB,
  design_suggestions JSONB,
  status VARCHAR(50) DEFAULT 'draft',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  version INTEGER DEFAULT 1
);
```

## 🐛 Common Database Issues & Fixes

### Issue 1: "Column Does Not Exist" Error

**Symptom:**
```
Failed to save wireframe: column "suggested_components" of relation "wireframe_artifacts" does not exist
```

**Root Cause:**
Database schema is missing new columns added to the TypeScript model. The code tries to INSERT/UPDATE columns that don't exist in the table.

**Solution:**

#### Option A: Automatic (Recommended)
The application now automatically adds missing columns on startup via `/backend/src/config/initializeDatabase.ts`:

```typescript
// Runs automatically on server start
await addColumnIfNotExists('wireframe_artifacts', 'suggested_components', 'JSONB');
await addColumnIfNotExists('wireframe_artifacts', 'design_suggestions', 'JSONB');
```

**Just restart the server and it will fix itself.**

#### Option B: Manual SQL
If automatic initialization fails, run these commands directly in PostgreSQL:

```sql
-- Add suggested_components column
ALTER TABLE wireframe_artifacts
ADD COLUMN IF NOT EXISTS suggested_components JSONB;

-- Add design_suggestions column
ALTER TABLE wireframe_artifacts
ADD COLUMN IF NOT EXISTS design_suggestions JSONB;
```

**Related Files:**
- `backend/src/config/initializeDatabase.ts` - Database initialization
- `backend/src/models/WireframeArtifact.ts` - Model definition

### Issue 2: Constructor Parameter Order Bug

**Symptom:**
Wireframe data appears corrupted after being saved and retrieved from database.

**Root Cause:**
In `WireframeArtifact.mapToArtifact()`, constructor was called with parameters in wrong order:
```typescript
// ❌ WRONG (before fix)
const artifact = new WireframeArtifact(row.project_id, row.title, row.design_type);
```

**Solution:**
Correct parameter order must match constructor signature:
```typescript
// ✅ CORRECT (after fix)
constructor(title: string, designType: string, projectId?: string) { ... }

// Call with correct order:
const artifact = new WireframeArtifact(row.title, row.design_type, row.project_id);
```

**Status:** ✅ FIXED in current codebase

**Related Files:**
- `backend/src/models/WireframeArtifact.ts:148`

### Issue 3: Suggested Components Not Persisted

**Symptom:**
- Wireframes are generated successfully with `suggestedComponents` and `designSuggestions`
- But when fetched from database, these fields are empty or missing

**Root Cause:**
The fields were generated by `wireframeService` but never saved to the database.

**Solution - 3 Parts:**

#### Part 1: Store in save() method
```typescript
// In WireframeArtifact.save()
artifact.suggestedComponents ? JSON.stringify(this.suggestedComponents) : null,
artifact.designSuggestions ? JSON.stringify(this.designSuggestions) : null,
```

#### Part 2: Retrieve in mapToArtifact()
```typescript
// In WireframeArtifact.mapToArtifact()
artifact.suggestedComponents = row.suggested_components ? JSON.parse(row.suggested_components) : undefined;
artifact.designSuggestions = row.design_suggestions ? JSON.parse(row.design_suggestions) : undefined;
```

#### Part 3: Return in API responses
```typescript
// In wireframeRoutes.ts - POST response
suggestedComponents: artifact.suggestedComponents || [],
designSuggestions: artifact.designSuggestions || [],

// In wireframeRoutes.ts - GET response
suggestedComponents: wireframe.suggestedComponents || [],
designSuggestions: wireframe.designSuggestions || [],
```

**Status:** ✅ FIXED in current codebase

**Related Files:**
- `backend/src/models/WireframeArtifact.ts:59-111`
- `backend/src/routes/wireframes.ts:110-113`
- `frontend/lib/api/wireframesApi.ts:21-22`

## 🚀 Prevention: Best Practices

### 1. **Model-First Approach**
Always update:
1. TypeScript Model (`/models/*.ts`)
2. Database Schema (`initializeDatabase.ts` OR manual SQL)
3. API Routes (add to request/response)
4. Frontend Types (`/lib/api/*.ts`)

### 2. **JSON Fields in JSONB**
When storing complex objects in JSONB columns:
```typescript
// ✅ CORRECT - Serialize before saving
JSON.stringify(this.suggestedComponents)

// Deserialize when retrieving
JSON.parse(row.suggested_components)
```

### 3. **Default Values**
Always provide defaults for optional fields:
```typescript
suggestedComponents: artifact.suggestedComponents || [],
designSuggestions: artifact.designSuggestions || [],
```

### 4. **Test the Flow**
After schema changes, test:
1. Generation: Does new data save?
2. Retrieval: Can you fetch the data back?
3. Type Safety: Do TypeScript checks pass?

```bash
npm run type-check  # Verify no errors
```

## 💡 Key Takeaways

1. **Database schema changes require code updates in 4 places**: Model → Save → Retrieve → API Response
2. **Use automatic schema initialization** to prevent "column does not exist" errors
3. **Always test end-to-end** after schema changes
4. **Document parameter order** in constructors to prevent bugs like the one fixed here
5. **Serialize JSONB fields** using JSON.stringify() and JSON.parse()
